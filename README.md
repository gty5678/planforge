## 当前最小范围

- 一个本地计划及计划起始日期
- 顶层任务和任意层级子任务
- 最末级活动支持施工、物流、验收、等待/养护和零工期里程碑
- 零工期节点正式作为“事件实例”：支持前序推导、预计发生、已实际发生和待发生四种状态
- 待发生事件会阻断后续任务；预计/实际事件使用明确时间参与重新排程
- 日期和星期自动按照真实公历对应
- 默认周一至周五工作，周末自动跳过
- 支持维护法定节假日和调休上班日
- 工作日历采用月历界面，以颜色区分默认施工、默认休息、手动施工和手动停工日期
- 点击日期即可设为施工日、不施工日或恢复默认规则，并可填写当天停工说明
- 横道图自动标出非工作日和系统当天日期
- 独立“时标网络图”页签按真实日期和时刻绘制活动：有施工段的工序折叠为倒数第二级汇总节点，未分段任务仍单独保留，并自动避让并行活动
- 可选的任务最早开始日期
- 汇总任务的最早开始日期会同步到全部后代任务；在该汇总任务下新增任务也会自动继承
- FS、SS、FF、SF 四类任务关系
- 可单独维护“作业模板库”：一个模板内部可包含施工、搬运/物流、审批/验收、等待/养护和事件等多个步骤
- 每个模板步骤可保存角色、默认工种、工期、工作/自然日历、噪音限制、说明；事件可默认设为“待现场确认”并阻断后续
- 模板内部步骤之间可定义 FS/SS/FF/SF、间隔、日历单位和业务类别
- “从模板创建作业”可一次生成汇总作业、全部任务/事件实例以及关系链
- 不同作业模板之间仍可定义衔接规则；重新排期时按同一上级范围继承为实例关系
- 两道已分段工艺按对应段生成 A1→B1、A2→B2，不生成 A1→A2 这类同工艺内部顺序
- 工艺库继承关系标明来源并由模板统一管理；手工关系保留且在重复时优先
- 时间关系保留工艺、材料、图纸、验收、移交、手续/法规和物流等业务类别
- 关系间隔可分别选择自然日或工作日
- 工期内部按分钟保存（1 工日 = 8 小时），最小可输入 5 分钟
- 活动可选择按工作日历累计或按自然连续时间累计
- 施工段不再强制至少 1 工日，可将 10 工日细分为 16 套、每套 5 小时
- 划分施工段时自动迁移原任务关系：进入关系接首段，离开关系接末段
- 横道图支持按层级筛选、逐项展开收起和横向缩放
- 编辑已分段的汇总工序总工期时，自动平均重新分配各施工段工期
- 任务可选择杂工、泥瓦工、水电工、木工、油漆工、安装工，横道图固定按工种着色
- 汇总任务的下级工种一致时沿用工种颜色，混合工种时使用默认深蓝色
- 任务关系支持多选批量删除，也可选择一条逐段关系后删除整组流水关系
- 任务表和横道图在各自层级内按计算开始时间自动升序排列
- 任务表支持逐项或全部展开收起，并在重新排期后保留展开状态
- 任务表支持拖放调整父子层级：拖到任务中间成为子任务，拖到行间保持同级
- “新增同级任务”按当前选择确定层级；点击空白或按 Esc 可取消选择，依赖选择的操作会自动禁用
- 项目可自定义每日一个或多个工作时段，例如普通班、冬夏季作息或两班制；午休和夜间加班会扩展有效施工时段
- 可分别允许双休日及节假日加班；未允许时仍遵守项目逐日工作日历
- 无约束任务起始日期、要求完工日期、排程基准日期、工作制度和噪音总规则统一在“项目设置”中维护
- 设置要求完工日期后，状态栏持续显示预计按期、提前或延期天数
- 启用排程基准日期后，基准日前已有任务保持原时间，其余任务不得重新排到基准日前
- 排程优化目标支持“尽量保持原计划”“最早完成项目”和“尽量减少班组切换”；减少切换时优先把同一汇总任务下已具备条件的施工段成组安排，并自动与穿插方案比较，只有不拖晚项目完工时才采用整组衔接
- 班组可设置每天最大工时，并可选择限制连续工作天数；达到上限时自动插入休息时间
- 自动资源平衡支持冲突顺延，或允许超负荷继续排程并在排程原因中明确警告
- 任务可标记“产生噪音”；有噪音任务强制按工作日历执行，不得跨休息日或法定休息日施工
- 项目设置可选择“无视噪音施工限制”，开启后有噪音任务按自身选择的工作或自然日历排程
- 横道图可缩小到周视图，缩小时自动标注每周一日期
- 横道图滚轮缩放，Ctrl＋滚轮上下滚动，Shift＋滚轮左右滚动；缩放滑块同步更新，鼠标指向的时间位置尽量保持不变
- 有约束日期的任务链可早于全局计划日期开始；全局日期只作为无约束独立任务的起点
- 拖放后自动展开父级、选中并定位被移动任务；收起的汇总任务显示下级数量
- 任务关系窗口支持按任务名称模糊搜索、自动筛选和循环跳转匹配关系
- 汇总任务工期按计算开始至计算完成之间的自然日显示，首尾日期均计入且包含双休日；末级任务仍按工日排期
- 横道图中的末级工作任务按真实工作时段分段显示，午休、夜间、周末和节假日留白；汇总任务保持自然时间连续跨度
- 等待/养护等自然连续时间活动保持连续横道，不按工作班次拆段
- 下方横道图可按当前层级、展开状态和缩放比例，将全部任务与完整日期范围导出为一张 PNG 图片
- 横道图预览采用冻结窗格：横向滚动时固定左侧任务栏，纵向滚动时固定顶部日期栏
- 横道内部显示工序名称，空间不足时自动省略；放大后显示更多文字，导出图片同步保留名称
- 可选显示关键路径：控制项目最终完成日期的工序以红色突出；同时追踪四种工艺关系、间隔工期，以及班组、作业面、设备和路径形成的实际资源驱动链
- 时标网络图规范显示月/日双层时间刻度、非工作日底纹、项目起止节点、活动编号/名称/工期，以及带时距单位的 FS、SS、FF、SF 关系；关键控制链从项目开始连续连接到项目完成，并以红色粗线标出工艺、资源顺序和开放事件驱动关系
- 同一对分段工序之间的多条流水关系在网络图中归并为一条汇总关系并标注数量，汇总内部关系不绘制自环
- 时标网络图支持滚轮缩放、横纵滚动、关键路径开关，并可将完整日期范围和全部活动导出为 PNG 图片
- 流水关系的逐段最小间隔按自然日计算（包含双休日），普通任务关系仍按工日计算
- 每条任务关系可设置间隔自然日（包含双休日和节假日）；清理等实际作业应单独建立任务
- 任务关系支持选中编辑或双击编辑
- 可把一道工序按总工期生成多个独立施工段，不再自动建立 A1段→A2段的固定串行关系
- 多个施工段可由多个匹配班组并行执行；A1段→B1段等跨工序关系继续作为工艺约束保留
- 可在两道同段数工序之间自动建立逐段流水关系
- 作业面与资源分开维护：作业面、通行区域属于空间对象；班组、设备、检查人员属于施工资源
- 路径网络由装卸点、电梯口、交叉口、作业面入口等节点和有向/双向路段组成
- 每个路段可设置为“路径”或“作业面＋路径”，统一参与空间容量计算，避免同一现场区域重复建模
- 路段除逐日通行日历外，还可设置固定开放/停用日期，以及由“作业面移交”“临时道路拆除”等里程碑动态启用或停用
- 普通施工任务占用路径型作业面时，可选择正常共享、降低部分通行容量或施工期间完全封闭
- 路线模板按顺序组合多个路段，可设置替代路线；生成物流作业时首选路线不可用会自动改走替代路线
- 分段运输任务分别占用对应路段，只有同时使用同一路段且超过容量时才发生冲突
- 施工期间长期封闭路径时，可在普通任务中直接勾选对应通行路段并持续占用
- 任务分别选择“作业面/通行区域”和“占用资源”，任务表也分列显示
- 一个班组可配置一个或多个工种能力；任务所需工种与班组能力不匹配时禁止分配
- 任务只填写所需工种能力，不手动指定执行班组；排程器从能力匹配的可用班组中自动选择最早可开工者
- 自动派班采用连续施工软约束：不推迟最早开工时，优先沿用直接前序、同一作业面或同一上级工序的原班组
- 单个任务排程期间班组不可被切走；只有连续性会推迟工期或违反硬约束时才改派其他班组
- 计算得到的执行班组作为排程结果显示，不再混入作业面、设备等“占用资源”列表
- 没有能力匹配的可用班组时，施工和物流任务保持待排且不生成日期；其后续任务同步等待
- 每个班组可独立维护逐日上班日历，默认跟随项目工作日历，并可按日期设置上班、休息或恢复默认
- 排程会避开班组休息日期；多个能力匹配班组可选时，优先选择能够更早开工并完成的班组
- 在施工资源中选择班组后可查看“实际排班”：左侧月历高亮全天或部分时段有工作的日期，点击日期后右侧显示当天的时间段、工时、任务和作业面/路径，也可切换查看全部日期
- 活动可同时占用多个资源；资源冲突时自动顺延并显示等待原因
- 修改工期后重新排程会沿用上一次已形成的班组、作业面、设备和路径先后顺序；避免资源重新洗牌造成“工期增加、总工期反而缩短”，新任务仍会自动寻找可用班组和空档
- 流水关系只建立逐段工艺约束，班组或现场条件不足时允许显示真实间断
- 自动计算最早开始和完成日期
- 汇总任务自动汇总子任务日期
- 横道图及关系连线
- SQLite 自动保存
- “约束总览”统一展示时间、事件/状态、班组能力、空间和设备约束

当前不包括成本、基线和多项目管理。

## 第一版排程模型

时间轴上的基本实体分为两类：

- **任务实例**：持续执行，有开始和完成时间，可消耗班组、设备和作业面容量。
- **事件实例**：瞬时发生，不消耗连续工期，用于表示图纸批准、材料到场、验收通过和作业面移交等事实。

两类实体通过约束进入同一个排程器。FS/SS/FF/SF 是时间约束；班组与设备是资源容量约束；作业面与通行区域是空间容量约束；事件的预计、实际或待发生状态是现场状态约束。一个空间对象可以同时承担作业面和运输路径角色，施工任务按“共享、部分占道、完全封闭”扣减其通行容量。动态新增的作业面或路径用开放事件作为门槛，事件未发生时相关任务保持待排，事件发生后重新排程即可投入使用；停用日期或停用事件之后则不再允许任务跨越。资源竞争形成的实际先后顺序属于排程结果，不会被保存成固定工艺关系；重新计算时会把上次结果作为稳定顺序继续使用，遇到新的工艺关系冲突时以工艺关系为准。

作业模板库位于实例层之上：模板不是直接参与计算的任务，而是由多个“任务/事件步骤模板”和关系构成的小型标准流程。例如“自流平作业”可依次包含施工图批准事件、材料搬运、基层验收、自流平施工、养护和验收通过事件。点击“从模板创建作业”后才生成参与排程的任务/事件实例；模板关系在排程前同步为实例约束，手工建立的项目特有关系仍独立保存。

建议的现场用法：先新建“事件/里程碑”，设置为“待发生”来阻断后续施工；现场确认后改成“已实际发生”并填写时间，重新排程即可看到受影响任务的新时间。

## 启动

```powershell
cd C:\Users\yin\Desktop\MM
uv sync
uv run construction-schedule
```

依赖以 `pyproject.toml` 和 `uv.lock` 为准，`uv sync` 会自动创建或更新项目内的 `.venv`。在 VS Code 中直接按 F5，会先执行一次锁定版本的 `uv sync --frozen`，再使用这个 uv 环境启动并调试软件。

数据保存在 `data/schedule.db`。旧版的 `data/construction.db` 不再使用，但不会自动删除。

任务定义与排程输出分别存储：`tasks` 只保存名称、工期、约束等计划输入；每次计算会创建一条 `schedule_runs`，并把任务的起止时间、班组、时差和原因写入 `task_schedule_results`。历史运行不会被后续重排覆盖，可通过当前运行标记切换读取版本。旧库中的 `calculated_start`、`calculated_finish`、`calculated_crew_id` 和 `schedule_reason` 会在首次启动时迁入“迁移前当前计划”，随后从 `tasks` 表移除。

## 四种任务关系

- FS：前置任务完成后，后续任务开始。
- SS：前置任务开始后，后续任务可以开始。
- FF：前置任务完成后，后续任务才能完成。
- SF：前置任务开始后，后续任务才能完成。
